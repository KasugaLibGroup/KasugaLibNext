# 分层动画状态机原理

数据 schema、动作/守卫引用和绑定方式见 [API reference](../reference/fsm.md)。

业务上，状态机负责回答“角色或装置现在为什么处于这个动作”，不负责决定模型怎样上传。运行时把它包装成 `AnimationScope` 的 Controller：Scope 提供固定的逻辑步和输入快照，FSM 选择状态并合成姿态，最终的 `PoseOutput` 通过结果型 Target 交给渲染端。

## 定义与实例

状态机定义描述变量、并行层、状态和转移，资源重载时载入定义注册表。运行实例保存当前状态、
状态时长、变量值和混合进度，不能把这些状态写回共享定义。
文件标识与机器的逻辑标识独立，宿主根据逻辑标识绑定实例。

## 状态推进与动作

每层有自己的状态图，tick 根据守卫、触发器和完成条件选择转移，并在相应阶段执行进入、退出、
更新和转移动作。内容引用代码侧注册的函数标识，避免在数据加载时执行任意代码。
瞬态触发器在 tick 周期结束清除，普通变量继续留在实例中。

一次宿主调用可以产生多个固定逻辑子步，状态机每个子步只推进一次。触发器、业务变量和本步播放视图在 Controller 执行前冻结；内部失败会回滚状态机 checkpoint，避免部分转移或半完成动作进入可见结果。联网时服务端继续承担业务权威，客户端副本只负责得到可渲染状态。

## 姿态混合

多个层按确定顺序合成姿态。基础层给出基准，累加层叠加局部动作，覆盖层按骨骼掩码替换指定范围。
转移期间在前后状态姿态之间按时间混合。组合结果先成为不可变的 `PoseOutput`，再由 `ModelPoseTarget` 按 publication 中的 previous/current 和连续性规则采样。渲染帧的 `interpolationAlpha` 只平滑显示，不推进状态机、播放时间或 revision。
公式轨道和动画片段都在提交逻辑步时求值，`query.*` 使用该步冻结的变量快照；渲染帧只插值最终 Pose，不再重新执行公式。依赖非线性公式的中间值因此按逻辑步采样近似显示，这是新抽象明确的时间语义。跨循环边界时结果标记为 `SNAP`，避免把 clip 尾端向起点错误插值。
结果包含骨骼局部变换、morph 权重和材质帧，之后进入统一的骨骼、IK 与物理流程。业务角色、方块装置和程序化宿主共用这一写入边界，具体模型格式不会进入 FSM 规则。

状态机负责动作时序；简单上下文到模型变体的选择可由 [Multiplexer](multiplexer.md) 承担。
两者可以组合，模型变体决定使用哪个实例，状态机决定该实例怎样运动。
