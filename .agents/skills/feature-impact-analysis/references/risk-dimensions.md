# 风险维度库

> **这是阶段 2 的查表依据。** 改动用 [01-impact-template.md](../assets/01-impact-template.md) 分析出来后，
> 对着这里逐维度判定，产出 [02-risk-template.md](../assets/02-risk-template.md) 的风险报告。
>
> **设计原则**：按**能力**组织，不按"改动类型"组织。
> 因为「涉及持久化」必然要问版本迁移，「涉及服务端客户端」必然要问网络同步——
> 这些后果是**能力的属性**，不是这次改动特有的。
>
> **每条维度给出**：风险是什么 · 什么改动必须查 · 检查项 · 严重度 · 典型失效。
> 检查项是**固定文本**，不许改写、不许跳过。觉得不对就改这个文件。

---

## 使用纪律

1. **改动的盘点表里「需要 = 是」的能力，其下所有维度必须逐条判定。**
2. **判定只有三种**：`有风险` / `无风险` / `待定`。
   - `无风险` 必须写**具体理由**（"因为 X 所以不会发生"），"不适用"不算。
   - `待定` 必须写**什么时候能定**。
3. **命中「未建的维度」时显式写「此维度未建」**，不许自行发明检查项。
   「我没有清单」比「我编一个清单」安全得多。
4. 每个 `有风险` 必须能对应到改动点清单里的某个 Cn。

# 一、持久化（PERSIST）

> 只要改动涉及**写进存档的数据**，以下 6 条全部要过。
> 即使你觉得"只是加个字段"，第 1、4 条也会咬人。

### R-PERSIST-1 版本迁移 · 严重度：致命

**风险**：旧存档读进新代码，字段缺失或改名 → NPE、数据丢失、世界加载失败。

**必查**：任何新增/改名/删除持久化字段，或改变已有字段的语义。

**检查项**
- [ ] 旧档（完全没有这个字段）加载后，代码拿到的是 null、默认值、还是抛异常？哪条路径会 NPE？
- [ ] 字段改名/删除时，有显式迁移代码吗？还是靠"读不到就用默认"？
- [ ] 迁移代码跑过一次后，会不会因为再次加载而重复执行（幂等吗）？
- [ ] 老玩家升级后的第一帧，表现出来的东西和他升级前看到的一致吗？

**典型失效**：新增字段在部分结构中缺失，读取方直接取值而未做存在性判断。

---

### R-PERSIST-2 兼容性 · 降级 · 严重度：严重

**风险**：玩家装了新版本存过档，再退回旧版本 → 旧版本读到不认识的字段，可能崩或丢数据。

**必查**：任何持久化结构变更。MC 玩家降级是常事（模组冲突、服务器未升级）。

**检查项**
- [ ] 新档里的额外字段，被旧版本读到时会怎样？忽略、报错、还是崩？
- [ ] 旧版本写回时，会不会把新字段**抹掉**？
- [ ] 这个功能有没有"只在新版本可用"的语义？如果有，旧版本该看到什么？

---

### R-PERSIST-3 一致性 · 多持有者 · 严重度：致命

**风险**：同一份状态被两处持有（本侧表 + 外部结构 / 服务端 + 客户端 / 内存 + 磁盘），两处不一致。

**必查**：数据存在两个以上地方，或跨服务端客户端。

**检查项**
- [ ] 这份数据有几处持有？**谁是权威**？（必须只有一个）
- [ ] 非权威方落后时，靠什么机制追上？追不上会怎样？
- [ ] 有没有"两边都改"的路径？冲突时以谁为准？
- [ ] 一份被改了，另一份不知道——怎么检测出来？

**典型失效**：旁挂缓存记录了 N 个元素，被挂靠的真实结构只有 M 个；读取第 i 个时越界崩溃。
外部结构是权威，本侧缓存是副本，两者漂移。

---

### R-PERSIST-4 跨存档 / 跨世界污染 · 严重度：致命

**风险**：数据串到别的世界/维度/存档。玩家开新档却看到上个档的东西。

**必查**：任何用**全局键**存的数据（UUID、静态字段、单例缓存），或跨维度共享的对象。

**检查项**
- [ ] 这份数据的作用域是什么？世界级、玩家级、还是全局？
- [ ] 玩家删档重开/换存档后，旧数据会被读到吗？
- [ ] 跨维度传送时，数据跟着走还是留在原维度？哪个是对的？
- [ ] 服务器多世界（Multiverse 类）场景下会串吗？

**典型失效**：世界被重建或删除后旧数据未清理，新世界里出现上一个世界的内容。

---

### R-PERSIST-5 卸载残留 · 严重度：严重

**风险**：玩家卸载 mod 后再打开存档 → 数据残留、加载失败、或静默丢失。

**必查**：任何新增的持久化数据。**这条最容易被漏**，因为它不在开发者的正常流程里。

**检查项**
- [ ] 卸载 mod 后，多出来的数据是**留在盘上**、**被清掉**、还是**导致加载失败**？
- [ ] 重新装回来时，之前的数据还能用吗？还是已经被清了？
- [ ] 卸载再装回，玩家看到的状态和卸载前一致吗？

**典型失效**：同 R-PERSIST-4——清理不彻底时，残留数据以「看不见但还在」的形式继续存在。

---

### R-PERSIST-6 重复加载幂等 · 严重度：一般

**风险**：同一份数据被加载两次（退出重进、崩溃后重进、热重载）→ 重复追加、计数翻倍。

**必查**：加载路径里有 `add` / `append` / 累加操作。

**检查项**
- [ ] 同一个存档连续加载两次，状态完全相等吗？
- [ ] 加载是"覆盖"语义还是"合并"语义？这次改动有没有改变它？

# 二、网络同步（NET）

> 只要改动涉及**服务端与客户端的交互**（哪怕只是"客户端发个请求"），
> 以下 6 条全部要过。其中「多玩家同步」与「区块外」是最容易出事的两个维度。

### R-NET-1 权威归属 · 严重度：致命

**风险**：客户端自己算结果，服务端也算，两边不一致 → 玩家看到的东西和实际不同。

**必查**：任何玩家可触发的状态变更。

**检查项**
- [ ] 这个结果由**谁**决定？服务端权威，还是客户端预测？
- [ ] 客户端预测错了怎么纠正？纠正时会跳变吗？
- [ ] 客户端能不能自己伪造结果（作弊面）？

---

### R-NET-2 多玩家同步 · 严重度：致命

**风险**：玩家 A 操作，B 看不到 / 看到旧的 / 看不到变化。

**必查**：任何影响其他玩家可见状态的操作。

**检查项**
- [ ] A 触发 → 服务端何时收到 → B 何时看到？这段延迟里两边画面差异有多大？
- [ ] B 需要看到的是什么粒度？（全量状态 / 变化事件 / 只看到结果）
- [ ] 两个玩家**同时**对同一目标操作，会怎样？串行化在哪做的？
- [ ] B 在 A 操作之后才加入，他能看到正确状态吗（初始同步）？

**典型失效**：联机时一方操作成功，另一方看不到或停在旧状态，且不会自行纠正。

---

### R-NET-3 丢包与乱序 · 严重度：严重

**风险**：旧包覆盖新状态；丢包导致永久不一致。

**必查**：任何走网络的**状态**同步（事件型同步风险较低）。

**检查项**
- [ ] 包里有版本号/序号吗？客户端怎么判断"这是旧的"？
- [ ] 丢了一个包，客户端会永远停在错误状态，还是下次会自动纠正？
- [ ] 有没有"最终一致"的兜底（定期全量）？

---

### R-NET-4 区块外 / 距离 · 严重度：严重

**风险**：对象跑出玩家附近的区块加载范围，逻辑停止 / 状态不同步 / 消失。

**必查**：任何会**移动**的对象，或可以超出玩家视距的东西（载具、弹射物等）。

**检查项**
- [ ] 对象在区块外时，它的状态由谁更新？
- [ ] 区块外的玩家能操作它吗？能看到它吗？
- [ ] 它在区块外变了状态，区块内的客户端怎么补上？
- [ ] 玩家自己离开范围时，本地状态怎么清理？回来时怎么恢复？

**典型失效**：可跨区块移动的复合实体在区块边界丢失状态同步。

---

### R-NET-5 断线重连 · 严重度：一般

**风险**：重连后状态是旧的 / 重复应用 / 丢失中间变化。

**检查项**
- [ ] 重连是拉全量还是接着上次？哪个对？
- [ ] 重连期间发生的变化，客户端怎么知道？

---

### R-NET-6 心跳与重放 · 严重度：严重

**风险**：周期性重放把某个时钟/计数器清零，导致动画/进度反复归零。

**必查**：任何"定期同步"机制。

**检查项**
- [ ] 同步是**事件型**（只在变化时发）还是**心跳型**（定期重发）？
- [ ] 心跳重放会不会重置客户端的时间/进度状态？
- [ ] 幂等吗？重放一次和重放十次结果一样吗？

**典型失效**：心跳重放时无条件重置时钟，循环动画永远只播前一小段；
若当前唯一被同步的动画恰好由公式轨道驱动，该缺陷会被**掩盖**而不易发现。

# 三、资源加载（RES）

### R-RES-1 缺失与降级 · 严重度：一般

**检查项**
- [ ] 资源找不到时：抛异常、返回空、还是用兜底？玩家看到的是崩溃还是缺模型？
- [ ] 路径大小写敏感吗？（`NKY` 曾因大小写错误读不出 MMD 模型）

### R-RES-2 重载有效性 · 严重度：严重

**检查项**
- [ ] 重载（F3+T / `/reload`）后，你持有的引用还有效吗？需要重取吗？
- [ ] 重载失败时，旧资源还在吗？

### R-RES-3 格式扩展边界 · 严重度：严重

**必查**：新增资源格式（如多格式模型加载器）。

**检查项**
- [ ] 新旧格式靠什么区分（扩展名 / 文件头 / 内容嗅探）？区分错了会怎样？
- [ ] 新格式解析失败时降级到谁？
- [ ] 扩展后**原有格式的加载路径有没有被改变**？（回归风险最高点）

---

# 四、模型与资产加载（MODEL）

### R-MODEL-1 坐标系约定 · 严重度：严重

**检查项**
- [ ] 这个格式的朝向/缩放与 Minecraft 约定一致吗？（bbmodel 与 gltf 常不一致）
- [ ] 缺法线/切线/UV 时，是补默认值还是画错？

### R-MODEL-2 顶点属性匹配 · 严重度：严重

**必查**：接入新格式。

**检查项**
- [ ] 新格式的顶点属性（位置/法线/UV/切线/骨骼索引/权重）与现有管线对得上吗？
- [ ] 缺的属性怎么补？补错了会变成 NaN 或全黑吗？

### R-MODEL-3 动画通道语义 · 严重度：严重

**检查项**
- [ ] TRS 通道语义一致吗？**morph target 权重支持吗**？
- [ ] 空轨道/空轴的默认值是恒等值吗？（SCALE 的恒等值是 1，不是 0）

**典型失效**：空轴 fallback 取 0 而非恒等值 1 → 变换矩阵奇异 → NaN 与 Inf 污染法线。

### R-MODEL-4 规模与内存 · 严重度：一般

**检查项**
- [ ] 大模型（几十万顶点）加载会卡主线程吗？
- [ ] 零位移的 morph 定义被跳过了吗？（否则小堆内存爆）

---

# 五、注册（REG）

### R-REG-1 顺序依赖 · 严重度：致命

**检查项**
- [ ] 注册之间有父子/依赖关系吗？怎么声明的？
- [ ] 父未解析时子会怎样？报错还是静默失败？

**典型失效**：注册组父子依赖未做拓扑排序，子项先于父项解析导致静默失败。

### R-REG-2 重复与覆盖 · 严重度：严重

**检查项**
- [ ] 同一对象注册两次会怎样？报错、覆盖、还是两个都留着？
- [ ] id 撞了会怎样？

**典型失效**：同一内容被重复加入创造栏；根变换被应用两次导致位置翻倍。

### R-REG-3 副作用外溢 · 严重度：严重

**风险**：新注册的东西触发了"别人"挂在上面的逻辑。

**检查项**
- [ ] 新注册的物品/方块会触发成就、进度、配方解锁吗？
- [ ] 它会被自动加进某些创造栏 / 战利品表 / 标签吗？
- [ ] 这些自动行为是你要的吗？

**典型失效**：新增物品首次获得时误触发无关成就（成就条件未按物品类型解耦）；
新增方块同时出现在多个创造栏；创造栏内物品顺序与预期不符。

# 六、编解码（CODEC）

### R-CODEC-1 失败语义 · 严重度：一般

**检查项**
- [ ] 编解码失败返回什么？调用方都在检查吗？

### R-CODEC-2 往返等价 · 严重度：一般

**检查项**
- [ ] 编码→解码往返后完全相等吗？（可选字段/默认值常在这一步丢）

# 七、渲染（RENDER）

### R-RENDER-1 像素级正确 · 严重度：严重

**风险**：中间变量全对，屏幕上是错的。

**检查项**
- [ ] 你断言的是**像素**还是中间变量？
- [ ] alpha 通道检查了吗？（RGB 对但 A 错 = 透明/全黑）
- [ ] 混合模式、深度写入、面剔除在渲染前后**复位**了吗？

**典型失效**：顶点色携带亮度信息导致整体变黑；法线为 NaN 导致光照全黑。
世界 UI 把整个 GUI Z 范围压缩到很薄的世界平面，字体主体/阴影在透视深度中量化为相同值，
出现条纹、缺块和边框闪烁；二维 RGBA 画布的 RGB 已预乘 alpha，合成时再次乘 alpha 会形成黑边。
只测试 GUI Z=0 会遗漏端点裁剪：MAX_GUI_Z 上字体阴影的 +0.03 偏移仍可能超出近裁剪面，
需同时检查端点、阴影像素与世界面板位置。
第三方控件的透明 hover/focus 描边若使用替换目标 alpha 的混合方式，会擦除离屏画布底色；
必须分别读取默认、hover、focus 的实际 RGBA，且兼容修复只能作用于目标 mod 的绘制作用域。

### R-RENDER-2 NaN / Inf 传播 · 严重度：严重

**检查项**
- [ ] 输入可能出现 0、极小数、负数吗？除法/求逆有守卫吗？
- [ ] 输出有 NaN/Inf 哨兵扫描吗？

**典型失效**：尺寸为 0 时缩放矩阵退化，产生 NaN 并沿层级传播。

### R-RENDER-3 与其他渲染模组共存 · 严重度：严重

**检查项**
- [ ] 装了 Iris / OptiFine 类模组，你的 pass 会被跳过吗？跳过时**报错还是静默**？
- [ ] 你的 shader / 顶点格式与它们冲突吗？

**典型失效**：与同类模组共存时渲染崩溃；着色器类模组会让本模组的注入点被静默跳过。

### R-RENDER-4 文本与非 ASCII · 严重度：严重

**检查项**
- [ ] 中文等非 ASCII 字形渲染过吗？换过多个颜色测吗？
- [ ] 字体渲染会不会叠加两次（重影）？

**典型失效**：文字颜色参数被上游忽略，无论传入什么色号都渲染为同一颜色；
同一段文字被绘制两遍形成重影。现有渲染回归场景对非 ASCII 字形零覆盖。
2026-10-22 世界 UI 反馈还暴露了字形与阴影的微小 Z 层级在世界透视下丢失的问题；
新增画布 GPU 深度回归只验证层级与像素，不能代替真实字体、中文和控件的客户端验收。

---

# 八、空间与坐标（SPACE）

### R-SPACE-1 参照系失效 · 严重度：致命

**风险**：对象被拆分/合并/传送后，原坐标系不再成立，但代码还在用。

**必查**：任何"对象自带局部坐标系"的改动（载具、可拆分复合结构）。

**检查项**
- [ ] 坐标系原点在哪？跟着谁走？父对象移动时更新吗？
- [ ] 对象被拆分/合并/传送后，坐标系需要重建吗？谁负责？
- [ ] 切换参照系的那一帧，插值会出错吗？（两系之间线性插值 = 抽搐）

**典型失效**：局部坐标系与玩家操作坐标系的换算约定未对齐，玩家无法从视觉上推断出正确位置。

### R-SPACE-2 远坐标精度 · 严重度：一般

**检查项**
- [ ] 对象离原点极远时（如 3000 万格），浮点精度够吗？

---

# 九、状态机 / 动画（FSM）

### R-FSM-1 临时态与中断 · 严重度：严重

**检查项**
- [ ] 有临时态（过渡态）吗？过渡态期间被打断会怎样？
- [ ] 两个客户端把状态推到不同值，谁赢？

### R-FSM-2 时钟驱动方式 · 严重度：严重

**检查项**
- [ ] 时钟是 tick 驱动还是时间驱动？两者插值不一致会看到什么？
- [ ] 状态未变但被重新 conform 时，时钟会被清零吗？

**典型失效**：见 R-NET-6——同一问题从时钟侧观察。

---

# 十、时序（TICK）

### R-TICK-1 条件判定粒度 · 严重度：严重

**检查项**
- [ ] 触发条件是"瞬间满足"还是"持续 N tick"？两者玩家能感知差别吗？
- [ ] 同一 tick 内多次满足条件会重复触发吗？需要最短间隔吗？

### R-TICK-2 极端速度 / 跨越 · 严重度：严重

**风险**：前一 tick 未达条件，后一 tick 远远超出 → 中间状态被跳过。

**检查项**
- [ ] 高速运动时一 tick 移动多少格？判定用的是"当前点"还是"位移区间"？
- [ ] 卡顿追赶（一次跑多个 tick）时行为正确吗？

**典型失效**：高速移动对象在单 tick 内跨越判定边界。

### R-TICK-3 双端 tick 相位差 · 严重度：一般

**检查项**
- [ ] 客户端与服务端 tick 有相位差时，玩家看到什么？

---

# 十一、事件与生命周期（LIFE）

### R-LIFE-1 清理真被执行 · 严重度：致命

**风险**：写了清理逻辑，但那个钩子根本没被调用，或调用时参数是 null。

**检查项**
- [ ] 你挂的清理逻辑，**真的会被调用吗**？有证据吗（不是"应该会"）？
- [ ] 传进去的参数有效吗？（有没有先 remove 再 get 的经典错误）
- [ ] 世界退出 / 玩家退出 / chunk 卸载，三种生命周期各挂在哪？漏了哪个？

**典型失效**：清理钩子里先移除再查询，取到 null 当作参数传给下游；下游按 key 查不到对象，
`close()` **永不执行**，运行时与线程持续泄漏。

### R-LIFE-2 生命周期覆盖 · 严重度：严重

**检查项**
- [ ] 对象有哪些销毁路径？（正常删除 / 区块卸载 / 世界删除 / 服务器关闭）
- [ ] 每条路径都清理了吗？漏一条就累积孤儿数据。

**典型失效**：文本编辑按 Esc 后只清容器焦点，嵌套 EditBox 仍处于 focused，下一帧重新接管；
旧 held key 的 repeat 在退出后触发游戏移动，或未知键统一以 key=-1 索引导致不同 scanCode 的松键丢失。

---

# 十二、第三方集成（XMOD）

### R-XMOD-1 注入冲突 · 严重度：致命

**检查项**
- [ ] 注入的目标方法/字段，其他 mod 也大概率注入吗？
- [ ] 两方注入同一处，谁生效谁被跳过？**报错还是静默跳过**？
- [ ] **你怎么确认这个 mixin 真的生效了？**（不能假定）

**典型失效**：两个模组注入同一方法时后者被静默跳过，日志仅一行
`Method overwrite conflict ... Skipping method.`，功能坏了但游戏不报错；
或注入点冲突直接抛 `MixinApplyError`。
键盘后置事件即使取消，也可能晚于原版 KeyMapping/快捷键副作用；验证必须调用真实入口并检查游戏按键状态。

### R-XMOD-2 挂靠外部数据结构 · 严重度：致命

**检查项**
- [ ] 你能直接改对方的私有字段吗？改了在对方更新后会不会**静默失效**（编译不报错）？
- [ ] 不能改的话，本侧怎么旁挂？**谁的数据是权威**？
- [ ] 对方拆分/合并/销毁对象时，你挂的数据怎么办？
- [ ] 对方允许别人往它的对象上放东西吗？销毁时那些东西去哪了？
- [ ] 对方版本升级改了内部约定，你怎么发现？

**典型失效**：旁挂数据与外部结构各自演化出现漂移；外部对象销毁后旁挂数据残留为孤儿。

### R-XMOD-3 多方块 / 附着物 · 严重度：严重

**必查**：任何"承载第三方内容"的容器（载具、可拆分复合结构）。

**检查项**
- [ ] 对象上允许别家 mod 放方块吗？对象被拆分/销毁时，那些方块去哪了？
- [ ] 多方块结构跨在拆分边界上，拆完两边都残缺吗？
- [ ] 别家 mod 给对象加了自定义字段，你处理时会丢弃吗？

**典型失效**：可承载第三方内容的容器被拆分时，内容归属未定义。

### R-XMOD-4 物理侧差异 · 严重度：严重

**检查项**
- [ ] 客户端专用的类，在 dedicated server 上存在吗？
- [ ] 服务端环境跑过吗？（客户端专用类在专用服务端不存在，会直接加载失败）

# 十四、平台与原生（NATIVE）

### R-NATIVE-1 平台覆盖 · 严重度：致命

**检查项**
- [ ] 支持哪些 OS / 架构？arm64 与 x64 都有吗？
- [ ] 加载失败时：崩溃、异常、还是静默不工作？
- [ ] dedicated server 也需要它吗？
- [ ] 移动端 / 第三方启动器会怎样？

**典型失效**：特定发行版或内核下 JVM 直接崩溃；移动端与第三方启动器因命名空间限制加载失败（`UnsatisfiedLinkError`）；某些 JVM 实现下随机崩溃。

### R-NATIVE-2 完整性 · 严重度：严重

**检查项**
- [ ] 原生库有哈希/签名校验吗？文件已存在时是否直接信任？

**典型失效**：原生库下载后无校验，文件被替换或损坏时仍被信任并加载。
