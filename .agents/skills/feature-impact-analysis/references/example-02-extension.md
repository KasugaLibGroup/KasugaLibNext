# 示例二：为 model-loader 添加 bbmodel 格式支持

> **虚构设定**：当前代码里 bbmodel 已存在，本文假装它不存在，走一遍"新增一种格式"的完整分析。
> 真实开发时也是这个路径——参考已有格式（gltf / obj / mmd）的接入方式，再补差异。
>
> **这是三个示例中的「能力扩展」型。** 另外两个：
> - [example-01-gameplay.md](example-01-gameplay.md) —— **玩法功能**型，重心在**状态与同步**
> - [example-03-infrastructure.md](example-03-infrastructure.md) —— **基建**型，重心在**契约完整性**
>
> 扩展型关心的是「**转换语义对不对**」—— 与另外两类都不重叠。

# 阶段 1 产物 · 改动分析

## 0. 需求原文

```
为项目的 model-loader 能力添加 bbmodel 格式支持。
```

**补充澄清**：

- bbmodel 是 BlockBench 的工程格式，第三方建模者普遍使用。
- 目标是让作者把 bbmodel 直接丢进资源目录就能用，不需要先导出成 gltf/obj。

## 1. 归类

| 问题 | 答案 | 依据 |
|---|---|---|
| 玩家能直接感知吗？ | **间接** | 玩家看不到"格式"，但能看到模型是否正确显示 |
| 主要在用已有能力，还是造新能力？ | **扩展已有能力** | model-loader 已有 gltf / obj / mmd 三种格式 |
| 引入新的持久化数据吗？ | **否** | 纯读取，不写盘 |
| 涉及服务端与客户端的交互吗？ | **否** | 纯客户端渲染 |

> 归类结论：这是**能力扩展**，不是新玩法。
> 主导风险不是"状态不同步"，而是"**转换语义是否正确**"——坐标、UV、顶点属性。

## 2. 能力盘点

| # | 能力项 | 是否需要 | 用途说明 | 项目中是否存在且可直接用 | 最终可能改动的部分 |
|---|---|---|---|---|---|
| 1 | 存档持久化 | 否 | 只读取模型，不写任何存档数据 | — | 不涉及 |
| 2 | 网络同步 | 否 | 模型在客户端加载与渲染，不需要双端同步 | — | 不涉及 |
| 3 | 资源加载 | **是** | 从资源包/classpath 按路径读 `.bbmodel` 文件；贴图可能是外部文件或内嵌 base64 | 存在需改 | 可能要给 Source 增加 String/Binary 的读取路径 |
| 4 | 模型/资产加载 | **是** | 这是需求主体：把 bbmodel 的 JSON 树转成内部的 Model（含新增转换器） | 存在需改 | 新增解析器 + 转换器，接入现有管线 |
| 5 | 注册 | 否 | 不走 MC 的方块/物品注册 | — | 不涉及 |
| 6 | 数据驱动注册 | 否 | 不做成 datapack 可配 | — | 不涉及 |
| 7 | 编解码 | **是** | 解析 bbmodel 的 JSON 结构（elements / outliner / textures / animations） | 直接可用 | 复用现有 JSON 解析设施 |
| 8 | 渲染 | **是** | 顶点、面、材质要接进渲染管线，最终画出来 | 直接可用 | 产出 Vertex/Mesh/Material，不改造渲染层 |
| 9 | 空间与坐标 | **是** | **BlockBench 的旋转/原点语义与 Minecraft 完全不同**，必须转换 | 直接可用 | 新增一层变换转换（这是本次最大的技术点） |
| 10 | 状态机/动画 | 否 | 除非要支持 bbmodel 自带的动画段 | — | 若做动画则涉及，需在阶段 2 前定 |
| 11 | 时序 | 否 | 加载是瞬时行为，不跑 tick | — | 不涉及 |
| 12 | 事件与生命周期 | **是** | 资源重载（F3+T）后模型与贴图要能重新加载 | 直接可用 | 挂到现有重载事件上 |
| 13 | 第三方集成 | **是** | bbmodel 是 BlockBench 生态的格式，语义由对方定义 | 存在需改 | 需要一份"格式语义对照"（旋转、UV、单位） |
| 14 | 脚本运行时 | 否 | 不需要脚本暴露 | — | 不涉及 |
| 15 | 平台与原生 | 否 | 纯 Java 解析 | — | 不涉及 |
| 16 | 配置 | 否 | 格式支持不需要服主开关 | — | 不涉及 |
| 17 | 音效与粒子 | 否 | 加载模型不涉及播放 | — | 不涉及 |
| 18 | 领域规则 / 业务逻辑 | 否 | 无需业务判定规则 | — | 不涉及 |
| 19 | 其他新子系统 | 否 | 转换器属于「4 模型/资产加载」的新建实现，**不单列** | — | 不涉及 |

**不需要的能力及理由**

- 持久化 / 网络 / 时序 / 平台：本需求是"读文件 → 转内存对象 → 渲染"，不写盘、不走网络、不跑 tick。

**未定项**

- #10 动画：bbmodel 的 `animations` 段要不要支持？**这决定工作量差一倍**，必须在阶段 2 前定。

## 3. 逐维度判定

| 维度 | 关联改动点 | 判定 | 理由 |
|---|---|---|---|
| R-RES-1 | C6 | **有风险** | `.bbmodel` 找不到时是抛异常还是空模型？作者看到的必须是明确报错，不是"模型不显示" |

## 5. 应对方式

| 风险 ID | 应对 | 具体做法 | 代价 |
|---|---|---|---|
| K1 | **改设计** | 不直接把 BlockBench 变换塞进管线；**单独写一层变换转换**，把「绝对原点 + 父 pivot」fold 成相对变换。三件事必须显式处理：① pivot 先除 16 转成格单位再相对父 pivot 求原点；② 旋转按 **Z→Y→X** 复合（不是常见的 X→Y→Z）；③ 子变换在父已旋转的坐标系内应用。用 3 个已知模型的期望坐标做锚点 | 多一层抽象，转换代码约 150 行 |
| K2 | 加测试 | 对带旋转的分组断言欧拉角与朝向；用固定 fixture | — |
| K3 | 加测试 | 离屏渲染带方向性图案的贴图，断言像素位置（不只断言 UV 数值） | — |
| K4 | **改设计** | 转换时显式补默认值：法线按面法线算、切线按 UV 推导、权重全 0 且不注册骨骼 | 需要定义"缺失属性时补什么"的规则表 |

| K6 | 加测试 | 表驱动：outliner 为空 / element 无 faces / textures 缺失，断言错误信息包含字段名 | — |
| K7 | **改设计** | 内嵌贴图设大小上限（如 4MB，超限拒绝并报错）；解析放到加载阶段而非渲染首帧 | 大贴图作者需自行压缩 |

| K11 | 待定 | 需实测 Iris 下是否跳过 | — |
| K12 | 加测试 | 文件缺失时抛出带路径的异常，断言消息含路径 | — |

**统计**：改设计 4 · 加测试 6 · 推迟 1 · 待定 1

## 3. 自动化测试方案

**K1 原点链转换**（改设计后验证）

- 关联：R-SPACE-1 / C3
- 层级：纯 JVM
- 动作：用手写的 4 个 fixture（单层无旋转 / 单轴旋转 30° / **三轴同时旋转**（验证 Z→Y→X 顺序）/ 三层嵌套含位移），
  断言转换后每个部件的世界坐标与朝向，与 BlockBench 预览手动记录的期望值一致
- 为什么是这一层：变换是纯数值计算，纯 JVM 秒级且能长期回归；进游戏看不出"差 0.3 格"
- 验收：每个 fixture 的每个部件，坐标误差 < 0.01，朝向夹角 < 0.5°
- 对应的实测项：M2

**K3 UV 方向**

- 关联：R-RENDER-1 / C4
- 层级：离屏 GL
- 动作：构造 2×2 棋盘格贴图贴在单面上，离屏渲染后断言四个象限的像素颜色位置
- 为什么是这一层：UV 数值正确不代表贴图方向正确，只有像素能证明
- 验收：左上象限颜色 = 期望的左上色块；四象限无镜像
- 对应的实测项：M3

**K4 缺失属性补默认**

- 关联：R-MODEL-2 / C4
- 层级：纯 JVM
- 动作：喂一个不含 normals/tangents 的 element，断言产出的 Vertex 里法线为单位向量、切线非零
- 为什么是这一层：属性补全是数据层行为，不需要 GPU
- 验收：法线长度 = 1.0±1e-3；切线非零且与法线垂直
- 对应的实测项：M1

**K5 扩展名与内容校验**（改设计后验证）

- 关联：R-RES-3 / C6
- 层级：纯 JVM
- 动作：① 造一个内容为 bbmodel 但后缀 `.json` 的文件 → 断言走错管线或被明确拒绝；
  ② 造一个后缀 `.bbmodel` 但内容不是 bbmodel → 断言报错含"format_version 缺失"
- 为什么是这一层：路由是纯字符串与结构判定
- 验收：两种情况都给出可定位的错误，不静默
- 对应的实测项：M6、M8

**K6 字段缺失的错误信息**

- 关联：R-CODEC-1 / C1
- 层级：纯 JVM
- 动作：表驱动——outliner 为空 / element 无 faces / textures 缺失 / 数组元素为 null，
  断言异常消息包含文件名与字段路径
- 为什么是这一层：错误构造在解析层
- 验收：每条都抛异常且消息含路径，不是 NPE 空指针栈
- 对应的实测项：M8

**K8 NaN 守卫**

- 关联：R-RENDER-2 / C3
- 层级：纯 JVM
- 动作：构造缩放为 0 的部件 → 断言变换矩阵可求逆或明确降级，输出无 NaN
- 为什么是这一层：矩阵运算可脱离 GPU 断言
- 验收：0 个 NaN/Inf
- 对应的实测项：M1

**K9 重载清理**

- 关联：R-RES-2 / C7
- 层级：纯 JVM
- 动作：模拟连续两次加载同一模型 → 断言旧 Model 引用被释放、贴图 id 未重复注册
- 为什么是这一层：引用与 id 管理是数据层行为
- 验收：第二次加载后贴图 id 数量不增长
- 对应的实测项：M7
